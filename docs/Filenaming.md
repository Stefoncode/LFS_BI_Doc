# File Naming
## 🔤  Recommended File Naming Convention for Mockups  
Use this structure to name both low-fidelity (wireframes) and high-fidelity (UI designs) mockups. It’s optimized for:
- distinguishing between versions and fidelities,
- structuring complex design projects,
- facilitating collaboration with UX, UI, Dev, and Product teams,
- keeping files clear and traceable across version control or shared drives.
***
## 🧩 Naming Structure
[Project]_[Platform]_[Page/Feature]_[MockupType]_[Version]_[Stateifneeded].ext
***
## ✍️ Element Details
|Element|Examples|Description|  
|-----------|-----------|-----------|  
|Project|ACME, CRM, eCommerce, IntranetV2...|Short name or code of the project|  
|Platform|WEB, MOB, TAB, RESP, DESK...|Target platform: Web, Mobile, Tablet, Responsive, Desktop|
|Page/Feature|LOGIN, DASHBOARD, PROFILE, CART...|Page name or functional zone|
|MockupType|WIREFRAME, MOCKUP, PROTOTYPE, FINAL|Type of asset: low-fi wireframe, UI mockup, prototype, or final deliverable|
|Version|V01, V02, V01b|Version tracking, useful for iterations|
|State|ACTIVE, DISABLED, LOADING, ERROR, SUCCESS, ALT|UI state (optional but helpful)|
|ext|.fig, .sketch, .xd, .png, .pdf, .drawio|File format|

## 📁 Concrete Examples
|Filename|Explanation|
|-------|-------|
|BiSalesCockpit_Desktop_DashboardElement_KPI_Scorecard_Wireframe_V01.png |Wireframe for BiSalesCockpit KPI Scorecard to be used in dashboard version 01 no state available|
|BiSalesCockpit_Desktop_DashboardElement_KPI_Scorecard_Mockup_V01.png|Mockup for BiSalesCockpit KPI Scorecard to be used in dashboard version 01 no state available|

## 🧠 UX Tips for File Management
Always use uppercase and underscores (_) for naming to ensure consistency across systems (Mac, Windows, Linux).
Avoid spaces and special characters in filenames.
